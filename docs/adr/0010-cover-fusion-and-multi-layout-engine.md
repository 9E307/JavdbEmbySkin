# 0010. 详情页封面融合模式（Cover Fusion）与四态排版引擎架构

## 状态
已接受 (Accepted)

## 上下文
JAVDB 的作品封面均为宽幅（接近 16:9 或大画幅比例），但在移动端或 Emby 双栏排版中，2:3 纵向海报更符合视听海报直觉。历史上曾出现“裁切海报模式（Crop，截断左侧）”与“全封面模式（Full，顶部大图）”两种偏好，但用户各执一词：裁切模式损失了部分原画信息，而全封面模式又占用过大屏幕垂直空间，导致下方标题和播放按钮被挤出首屏。

## 决策
我们决定**构建包含四大封面形态的动态排版引擎，并首创“封面融合模式（Cover Fusion，v7.257 重构）”**：
1. **四大排版形态自由切换**：
   * `crop`（经典裁切）：左上角基准平行锚定，原图右侧满铺；
   * `full`（全封面）：完整呈现，大图离开视口后顶部浮现紧凑信息条；
   * `fusion`（融合模式）：**顶态为纯正大封面，随着用户页面向下滚动，当下方标题触顶时，通过平滑补间矩阵收缩过渡为左侧两栏海报**；
   * `hybrid`（混合模式）：参考 Letterboxd 现代化三栏流式排布（左海报、中元数据、右操作与播放源）。
2. **滚动监听与防抖优化（v7.330 第一性原理加固）**：
   * 融合模式下的触顶收缩状态计算由 `requestAnimationFrame` 驱动，设置状态布尔切换锁，避免反复读取 DOM 引发高频强制回流（Forced Reflow）；
   * **绝对顶部守卫（Top Absolute Guard）**：当用户滚动回到页面顶部（`scrollY <= 30`）时，无条件强制恢复完整大图展开态（移除 `cover-fusion-collapsed` 类名与 `--fusion-shift`），从数学上 100% 杜绝因滞后死区或测量污染导致的“顶部 700px 空白卡死、大图丢失”；
   * **折叠态几何测量禁令（Measurement Poison Ban）**：在 `measureFusionMetrics()` 开头严格断言 `if (root.classList.contains('cover-fusion-collapsed')) return null;`。折叠态下海报与信息并排，`infoTop === heroTop`，若在此状态下测量将严重毒化 `titleTop` 缓存；
   * **物理安全保底**：展开大封面高度下，限制 `titleTop = Math.max(450, Math.round(measuredTitleTop))`，确保滞后死区 `titleTop - 80 >= 370px` 恒为正值；
   * **异步事件防抖**：图片 `load` 事件与窗口 `resize` 事件仅在展开态下才允许更新缓存，防止与液态玻璃（Liquid Glass）的 SVG Displacement 滤镜及 MutationObserver 产生重排竞态。

## 原因与权衡
* **终极调和视觉矛盾**：Fusion 模式兼顾了“进页面先瞻仰原图完整艺术感”与“往下滑动聚焦阅读信息与选播放源”的双重需求，解决了长久以来的版面争议。
* **硬件性能兼顾**：通过纯 CSS3 Transform 与 Opacity 过渡实现海报形态变换，GPU 单独合成渲染，不阻塞主线程。

## 结果与影响
* **收益**：
  * 全网首创的沉浸式详情页滚动融合动画，极大提升了用户视觉体验；
  * v7.330 彻底根治了在液态玻璃（Liquid Glass）下因强制回流导致的尺寸毒化与回滚卡死问题，实现百次滑动零卡顿、零空白、零残缺。
* **代价**：当用户在设置中切换封面展示风格时，必须彻底清理旧模式的动态监听器与 CSS 类，防止模式间样式污染。
