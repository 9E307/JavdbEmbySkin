# 0007. 被动采集熔断器与自定义纠错元数据永久保全

## 状态
已接受 (Accepted)

## 上下文
JAVDB 官方页面上存在元数据错误（如演员名字错漏、片商归类偏差、封面低清等），因此脚本提供了强大的“元数据纠错编辑器”，允许用户手动修正并加锁。与此同时，脚本具备“被动静默采集（Passive Collection）”能力，能在用户浏览网页时自动抓取作品信息并写入本地数据库。如果不加严格约束，被动采集极易将 JAVDB 官方的原生错误数据重新覆盖写回，摧毁用户辛辛苦苦完成的纠错成果；而在网络波动或 JAVDB 遭遇 Cloudflare 阻断时，异常的空数据还会导致本地收藏被清空。

## 决策
我们决定**确立被动采集熔断机制，并将用户自定义元数据 (`customMeta`) 置于不可逾越的最高法定保护层**：
1. **`customMeta` 绝对不可篡改与继承保护**：
   * 在被动采集 (`passiveCollectMovie`)、列表加载、或版本合并时，凡检测到既有记录包含 `m.customMeta`，必须完整继承 `chosenCustomMeta`，任何外部爬虫字段不得覆盖。
2. **被动采集防衰退熔断器 (Catastrophic Drop Circuit Breaker)**：
   * 在自动同步（如同步在线女优关注列表）时，若检测到远端获取的数据量发生灾难性锐减（例如 `onlineSet.size < 0.3 * cur.size`，远端获取不足本地 30%），立即触发安全熔断，中止自动覆盖，并记录告警日志。
3. **纠错自愈与云端校验 (Self-Healing Engine)**：
   * 提供“一键检查官方自愈（`runBatchCloudCheck`）”功能，仅当用户主动触发时，才去对比官方最新数据与用户纠错数据的差异，允许用户直观对比并决定是否采纳，绝不私自暗中修改。

## 原因与权衡
* **用户纠错是高成本的人工资产**：用户查阅资料并手动填写的番号别名、漏标女优是全库最珍贵的数据。机器爬取的便宜数据绝对不能逆向抹杀人类的高价值输入。
* **远端 DOM 的不可靠性**：如果 JAVDB 临时改版（例如 CSS 选择器变动），或者用户网络丢包只返回了半截 HTML，采集器若无脑同步就会误以为“用户删除了关注”而把本地数据全部清空。30% 熔断器是阻止灾难性数据丢失的坚固护栏。

## 结果与影响
* **收益**：用户纠错数据永不退化；在极端断网与反爬阻断下本地数据依然固若金汤。
* **代价**：在编写任何更新影片实体的函数时，必须使用结构化合并函数，禁止直接使用 `Object.assign(old, incoming)` 进行扁平覆盖。
