# 0008. JAVDB SPA 局部路由生命周期接管与原生浮层同步

## 状态
已接受 (Accepted，并在 v7.328 增补原生网格排版熔断修复)

## 上下文
JAVDB 网站采用部分单页应用（SPA）与 Turbolinks 机制：当用户在分类、搜索、排行榜或分页间跳转时，往往不会重新刷新整个页面，而是通过局部替换 DOM 和更新 `History API` 进行导航。早先版本中，这导致了严重的“事件堆叠（Event Listener Leak）”、“幽灵卡片容器（Ghost DOM Containers）”、“浮动遮罩未销毁阻塞点击”以及切回原生皮肤后排版完全错乱等问题。

## 决策
我们决定**建立完整的 SPA 路由拦截与生命周期守护机制，严格管理组件销毁与原生浮层同步**：
1. **全方位路由变动监听**：
   * 拦截 `history.pushState` 与 `history.replaceState`，监听 `window.popstate`，并辅以低频（200ms 防抖）轻量 URL 检测函数 `checkRouteChange`，确保任何形式的导航都能 100% 捕获。
2. **生命周期清理流水线**：
   * 路由切换时，必须主动销毁上一页面的专用定时器（如封面评分轮询、画廊懒加载）、断开上一页的 DOM 观察器，防止旧页面的异步请求返回后将脏数据塞入新页面。
3. **原生浮层与设置遮罩同步管理 (`SKIN_CHROME_SEL`)**：
   * 将 `#jhs-settings-mask`、`#emby-settings-panel` 等浮层明确纳入全局 Chrome 集合管理；按 `Esc` 键时优先捕获关闭设置面板。
   * 实现 `syncNativeOverlayGuard()`，当用户在原生模式与 Emby 模式切换、或关闭设置遮罩时，强制清理背景虚化残留与不可点击的透明遮罩。
4. **瀑布流与微徽章重排联动**：
   * 当卡片内部的共演女优折叠徽标（Stack Badge）被展开或收起时，显式调用 `WaterfallEngine.refresh()`，即时更新卡片位置与容器总高。
5. **原生网格排版彻底复原与排版引擎启闭熔断（v7.328 增补）**：
   * 在 `removeEmbyDOM()` 中补全对 `.movie-list` 容器的 `.emby-masonry` 与 `.emby-dynamic-focus` 类名清理；
   * 在 `WaterfallEngine.layout`、`schedule`、`ensureLayoutClasses` 与 `restructureGrid` 顶层强制注入 `if (!enabled) return;` 熔断守卫；
   * 彻底切断异步图片加载事件在原生模式下被动重新触发瀑布流计算的链路，根治 CSS Grid 与 translate3d 叠加引发的版面右偏错乱。

## 原因与权衡
* **解决局部渲染的“幽灵残影”**：如果不做 SPA 路由接管，用户从“收藏夹”点击某部影片进入详情页，收藏夹的 DOM 会潜伏在后台继续响应键盘快捷键；而当用户点浏览器后退时，详情页的样式又会残留在列表中。
* **原生共存承诺**：本脚本承诺“一键关闭皮肤、随时完美回退原生”。要兑现此承诺，必须做到样式、DOM 和监听器的绝对可逆销毁。
* **第一性原理抵御过度设计（v7.328）**：面对排版错位，拒绝推翻重构既有的 `removeEmbyDOM()` 稳定架构，通过精准定位“容器 Masonry 类名残留”与“引擎缺乏启闭熔断”两个核心支点，仅用 6 行代码实现零副作用、100% 原生网格还原。

## 结果与影响
* **收益**：长时间连续浏览无内存泄漏、前进后退丝滑无卡顿、原生/Emby 模式切换零残影、关闭皮肤后 JAVDB 原生 4/5 列 CSS Grid 排版 100% 完美复原。
* **代价**：任何新挂载的全局常驻事件、浮层或异步排版计算，都必须在路由清理与全局 `enabled` 启闭熔断中注册拦截逻辑。
