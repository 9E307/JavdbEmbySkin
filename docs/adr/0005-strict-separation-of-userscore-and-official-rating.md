# 0005. 用户主观评分与官方评分的物理隔离体系

## 状态
已接受 (Accepted)

## 上下文
在作品元数据中，存在两个层面的评分信息：一是 JAVDB 社区大众给出的客观综合评分（如 4.38 分，来自数百人评价）；二是当前用户本人对该影片的个人主观评价（1~5 颗星）。早期曾有方案尝试将它们归一化至同一个字段或共用星级组件，导致了严重的数据覆盖与认知混乱。

## 决策
我们决定**对用户主观评分 (`m.userScore`) 与官方社区评分 (`m.rating.score`) 实行绝对物理隔离与独立生命周期管理**：
1. **字段隔离**：
   * `m.userScore`：严格限制为整数 1~5，未打分时为 `undefined` 或缺省，**绝不允许存入 0 或赋默认值**；
   * `m.rating.score`：为浮点数 0.0~5.0，附带 `rating.count`（评价人数）与 `rating.text`。
2. **合并与导入优先级**：
   * 在非覆盖导入（`importJSON`）、被动采集（`passiveCollect`）和云端同步时，**本地已有的 `userScore` 享有最高排他性保护**，任何外界无评分记录不得将其冲掉：
     ```javascript
     const finalUserScore = (typeof old.userScore === 'number' && old.userScore > 0) 
       ? old.userScore 
       : ((typeof nv.userScore === 'number' && nv.userScore > 0) ? nv.userScore : null);
     ```
3. **UI 表达隔离**：
   * 卡片与信息条展示的黄色/金色星星严格对应 `userScore`（若有）或明确标明“用户评分”；官方分数显示为“4.2分 (120人)”，避免视觉混淆。

## 原因与权衡
* **保护用户核心资产**：用户对自己收藏的片子手动打星，是整个插件中最具情感价值和私密价值的数据。如果被爬虫抓取的官方浮动分覆盖，用户打分将被永久抹除。
* **零值与未评价的语义清晰性**：在星级系统中，`0` 不是“零分”，而是“未评分”。严禁将未评分转化为 0 分，否则在求平均值或筛选高分作品时会产生毁灭性的统计偏差。

## 结果与影响
* **收益**：彻底杜绝评分被官方爬虫污染；导入合并时用户主观意志得到绝对保全。
* **代价**：任何编写数据迁移、同步合并或卡片渲染的工程师，必须时刻辨析当前操作的是 `userScore` 还是 `rating.score`，不得随意合并。
