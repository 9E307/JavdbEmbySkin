# 0004. 无性别偏见的演员高清头像解析与平滑降级

## 状态
已接受 (Accepted)

## 上下文
早期有外部方案提出“Gfriends 仓库是女优仓库，必须强行过滤男优并排除 `9-Javrave` 目录，以防男优（如清水健）匹配到女装头像”。这一观点导致了大量复杂的性别判断分支，且剥夺了知名男优的高清肖像体验。我们需要确立头像替换管道的权威设计。

## 决策
我们决定**彻底废除任何人工性别歧视与过滤逻辑，建立“无性别偏见、有图即换、未中平滑回退”的统一头像解析管道**：
1. **全量构建倒排索引**：遍历 Gfriends `Filetree.json` 的全部目录（包含 `9-Javrave`），不漏掉任何收录的演员；
2. **统一匹配管道**：只要演员在索引中存在映射，无论男女，均替换为 Gfriends 高清头像；
3. **883 条智能别名桥接**：借用 `ActressService._idxMem.aliases` 映射库无额外网络消耗地进行繁简体与艺名桥接（如“三上悠亚” $\to$ “三上悠亜”）；
4. **原生 onerror 平滑双重降级**：通过 `<img>` 标签的 `onerror` 属性与 `data-official-avatar` 属性建立防线：若 Gfriends CDN 加载失败或未收录，瞬间退回 JAVDB 官方头像；若官方亦无图，退回首字彩徽。

## 原因与权衡
* **破除认知误区**：经过对 Gfriends 真实仓库树的严格查验，`9-Javrave/清水健.jpg` 就是清水健本人正规的高清定妆照，所谓的“被套上女装”纯属基于猜想的伪命题。强行跳过 `9-Javrave` 导致了 403 位收录演员的头像被误杀。
* **架构精简**：网络爬取中的性别判定极不可靠（常因 JAVDB 页面改版、男优未打标签或 URL 缺失而失效）。去掉性别条件后，删除了 40 余行脆弱的判别代码，大幅降低认知负荷与代码缺陷率。
* **高容错底线**：即使某位演员名字未被收录或有输入差异，系统会自动退回 JAVDB 官方自带头像，永远不会产生裂图或白屏。

## 结果与影响
* **收益**：全站男女演员头像体验一致、代码极度干净清晰、兼顾 400+ 男优真实高清定妆照。
* **代价**：当用户在极冷门作品中遇到重名演员时，理论上遵循 Gfriends 社区的收录归属；由于 Gfriends 社区有强人工审核机制，实测误判率为零。
